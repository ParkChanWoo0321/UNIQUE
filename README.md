# UN1QUE

> 축제 현장에서 누구나 간단하게 참여할 수 있는 **가장 작은 고유 숫자 게임** 백엔드 서비스

UN1QUE는 참가자가 `0000`부터 `9999` 사이의 숫자를 선택하고, 다른 참가자와 겹치지 않은 숫자 중 가장 작은 숫자를 제출한 사람이 우승하는 축제 참여형 이벤트입니다. 별도의 회원가입 없이 브라우저 쿠키로 참가자를 식별하며, 날짜별 참여 기록과 응모 번호, 추가 기회, 최종 결과를 관리합니다.

이 저장소는 참가자 응모부터 당첨자 선정까지 담당하는 Spring Boot 백엔드 프로젝트입니다.

## 게임 규칙

1. 참가자는 행사 날짜를 선택하고 서로 다른 숫자 3개를 제출합니다.
2. 여러 참가자가 제출한 동일한 숫자는 당첨 후보에서 제외됩니다.
3. 한 명만 제출한 숫자 중 가장 작은 숫자가 당첨 번호가 됩니다.
4. 참여 현황에 따라 운영자가 보너스 단계를 열면 모든 참가자에게 추가 응모 기회가 지급됩니다.
5. 게임 종료 시 서버가 당첨 번호와 당첨자의 전화번호를 운영자에게 반환합니다.

## 주요 기능

- **비회원 참여**: HttpOnly 쿠키 기반 토큰으로 별도 회원가입 없이 참가자를 식별합니다.
- **날짜별 독립 운영**: 행사일마다 참여 횟수, 전화번호, 응모 번호와 결과를 분리해 관리합니다.
- **최초 일괄 응모**: 참가자는 처음에 서로 다른 숫자 3개와 전화번호, 개인정보 동의를 함께 제출합니다.
- **중복 참여 방지**: 같은 날짜에 동일한 전화번호가 여러 참가자로 등록되는 것을 차단합니다.
- **보너스 응모 기회**: 최대 4단계까지 추가 기회를 열 수 있으며, 늦게 참여한 참가자에게도 해당 날짜에 열린 기회를 동일하게 적용합니다.
- **자동 당첨 번호 계산**: 제출 횟수가 정확히 한 번인 숫자 중 최솟값을 조회해 당첨자를 결정합니다.
- **실시간 상태 조회**: 참여 인원, 진행 단계, 열린 보너스 단계와 남은 응모 횟수를 제공합니다.
- **운영 환경 대응**: CORS, 보안 쿠키, 커넥션 풀과 행사 시간 설정을 환경변수로 관리합니다.

## 서비스 흐름

```text
참가자 초기화
    ↓
날짜별 참여 정보 생성
    ↓
숫자 3개 + 전화번호 + 개인정보 동의 제출
    ↓
참여 현황에 따른 추가 응모 기회 지급
    ↓
게임 종료 및 가장 작은 고유 숫자 계산
    ↓
당첨 번호와 당첨자 전화번호 확인
```

## 핵심 API

| Method | Endpoint | 설명 |
| --- | --- | --- |
| `POST` | `/api/participants/initialize` | 참가자 및 날짜별 참여 정보 초기화 |
| `GET` | `/api/participants/me` | 내 응모 내역과 남은 기회 조회 |
| `GET` | `/api/game/status` | 게임 진행 상태와 참여 현황 조회 |
| `POST` | `/api/game/entries` | 최초 숫자 3개와 전화번호 제출 |
| `POST` | `/api/game/submissions` | 추가 기회로 숫자 제출 |
| `GET` | `/api/game/result` | 당첨 결과와 본인 당첨 여부 조회 |
| `POST` | `/api/operations/bonus` | 전체 참가자에게 보너스 기회 지급 |
| `POST` | `/api/operations/finish` | 게임 종료 및 당첨자 계산 |
| `POST` | `/api/operations/recalculate` | 전체 행사일 응모를 합쳐 당첨자 1명 재계산 |

### 이틀 통합 당첨자 재계산

`POST /api/operations/recalculate`를 요청 본문이나 날짜 파라미터 없이 호출합니다.
설정된 전체 행사일(`EVENT_DATES`, 기본값 `2026-09-21,2026-09-22`)의 응모를 합쳐,
전체에서 정확히 한 번 제출된 숫자 중 가장 작은 숫자를 선정합니다.
같은 사람이 이틀에 걸쳐 같은 숫자를 제출했어도 두 번 제출된 숫자로 계산하여 제외합니다.
전화번호는 당첨 번호가 제출된 날짜의 참여 정보에서 가져옵니다.

응답 예시이며 아래 번호와 전화번호는 실제 당첨 정보가 아닙니다.

```json
{
  "eventDates": ["2026-09-21", "2026-09-22"],
  "winningNumber": "0003",
  "winnerFound": true,
  "winnerPhoneNumber": "01000000000",
  "calculatedAt": "2026-09-23T01:00:00Z"
}
```

응모가 없거나 모든 숫자가 중복이면 `winnerFound`는 `false`이며 번호와 전화번호는 `null`입니다.
호출할 때마다 현재 DB의 응모 데이터로 다시 계산하며, 기존 날짜별 결과가 있어도 호출할 수 있습니다.
이 API는 계산 결과를 반환만 하므로 응모 데이터와 `game_results`는 변경하지 않습니다.
따라서 기존 날짜별 결과 조회 API(`/api/game/result`)에는 통합 계산 결과가 반영되지 않습니다.
운영자 확인용 API로, 기존 운영 API와 마찬가지로 현재 별도 관리자 인증은 구현되어 있지 않습니다.

## 데이터 설계 특징

- 참가자 식별 정보와 날짜별 참여 정보를 분리해 동일한 참가자가 여러 행사일에 독립적으로 참여할 수 있습니다.
- 전화번호는 하이픈을 제거한 값으로 날짜별 참여 정보에 저장하며, 행사일과 전화번호 조합에 고유 제약조건을 적용합니다.
- 응모 번호는 개별 행으로 저장해 숫자별 제출 횟수와 가장 작은 고유 숫자를 데이터베이스에서 효율적으로 조회합니다.
- 게임 결과와 보너스 실행 기록에 고유 키를 사용해 중복 실행을 방지합니다.
